# Workspace service

IMPLEMENTED: create a workspace with an atomic OWNER membership, list a caller's workspaces, and get a workspace through membership authorization. Invitation persistence exists; invitation management is PLANNED.

Java 21, Maven, Spring Boot 4.1.1, JPA, Security, Bean Validation, PostgreSQL and Flyway. Dependency versions were retained. HTTP port: 8082. The service owns `workspace_db` (local Compose port 5433). It never connects to `user_db`.

## Local use

From this directory, start PostgreSQL using `docker compose up -d`, then run:

```powershell
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=local'
```

Supply your development user's UUID in `X-User-Id`. This header is a temporary, unverified development identity, accepted only under explicitly active `local` or `test` profiles. Never expose these profiles to untrusted clients. Both `prod` and `production` disable this adapter, even if local/test is also active. Default/production returns JSON 401 without a separately implemented trusted `CurrentUserProvider`. There is no JWT, Basic login, fixed user or production header fallback.

## API

| Method | Path | Result |
| --- | --- | --- |
| POST | `/api/v1/workspaces` | 201 + Location + WorkspaceResponse |
| GET | `/api/v1/workspaces` | 200 + array; empty when no memberships |
| GET | `/api/v1/workspaces/{workspaceId}` | 200 for member; otherwise 404 |

POST body: `{"name":"My Workspace"}`. Caller identity comes from `CurrentUserProvider`, never `ownerUserId` in JSON. Request validation rejects blank and raw names longer than 100 characters. Application validation strips surrounding whitespace and independently enforces canonical length 1–100. Internal create accepts the trusted owner UUID; one Spring transaction saves workspace and OWNER membership, rolling back both on failure.

Responses contain `id`, `name`, `createdAt`, `updatedAt`; UUID strings and ISO timestamps, never JPA entities. Membership-filtered JPQL performs both reads in the database. Missing and inaccessible IDs return the same 404 without checking existence separately. Reads are transactional/read-only.

Errors use `timestamp`, `status`, `error`, `message`, `path`, `fields`. Invalid input: 400; missing/untrusted identity: 401; unavailable workspace: 404; unexpected failures: generic 500. Database details and traces stay server-side.

## Persistence and tests

V1 is unchanged. Required columns, workspace foreign keys, unique `(workspace_id,user_id)`, role/status checks and existing query indexes are managed by Flyway. UUIDs are generated by JPA. All user references are UUID values without cross-service FKs. Invitation expiry is required by the existing V1 schema; no lifecycle rules or endpoints are implemented.

```powershell
.\mvnw.cmd test
```

Ordinary tests use isolated H2, Hibernate create/drop, and no Flyway. The opt-in PostgreSQL test uses real Flyway plus Hibernate `validate`, tests all three entity types and name, role, status, uniqueness and FK constraints. It is excluded from the ordinary suite by its `IT` suffix. Against an explicitly created disposable database:

```powershell
$env:WORKSPACE_POSTGRES_TEST_URL='jdbc:postgresql://127.0.0.1:55439/workspace_mvp_test'
$env:WORKSPACE_POSTGRES_TEST_USER='workspace_test'
$env:WORKSPACE_POSTGRES_TEST_PASSWORD=''
.\mvnw.cmd '-Dtest=WorkspacePostgresIT' test
```

Only database names `workspace_mvp_test` or `workspace_smoke_<hex>` are accepted. The test does not create/drop a database; provision a fresh disposable database first. Never point it at a working database. H2 is not evidence of PostgreSQL compatibility.
